# Заявки Datatour в WordPress

Откройте **Админка → Заявки Datatour → Открыть**.

Прямая ссылка: https://sales.datatour.by/wp-admin/admin.php?page=dtbf26-leads

Доступ есть только у администратора WordPress. В списке показаны дата по Минску,
имя, контакт, цель обращения и состояние email-уведомления. Внутри заявки доступны
все отправленные поля, выбранный отель, состав туристов, пожелания, источник и согласие.

Каждая новая валидная заявка сначала сохраняется в базе WordPress. Email отправляется
после сохранения, и его ошибка не отменяет принятую заявку. Статус «Передано серверу»
означает принятие письма почтовой функцией; он не подтверждает доставку в ящик.

Повторная отправка с тем же ID не создаёт вторую запись и не отправляет второе письмо.
Суточная очистка служебных ограничений не удаляет сами заявки. Записи закрыты от
публичного просмотра, поиска, REST API и стандартного экспорта WordPress.

Сохранение добавлено в версии 2.2.5. Содержимое заявок, отправленных до этого
обновления, автоматически восстановить нельзя: оно не сохранялось в базе.

Проверки: `php tests/forms.php` (включая сбой почты, отказ сохранения и права доступа)
и `node tests/frontend.cjs` с Playwright и Chromium. Эти тесты не отправляют реальные письма.

## Уведомления Telegram

Настройка: **Заявки Datatour → Telegram**.
Прямая ссылка: https://sales.datatour.by/wp-admin/admin.php?page=dtbf26-telegram

Администратор указывает токен бота из BotFather, числовой ID личного чата или группы
и включает уведомления. Перед личными уведомлениями получатель должен нажать
«Запустить» у бота. При сохранении сайт проверяет токен через Telegram по HTTPS.
Сохранённый токен не подставляется обратно в HTML формы и не попадает в GitHub,
публичную конфигурацию, ответы формы, журнал статусов или текст уведомлений.
На сервере также поддерживаются `DTBF26_TELEGRAM_BOT_TOKEN` в wp-config.php либо
переменная окружения `DATATOUR_TELEGRAM_BOT_TOKEN`; они имеют приоритет над настройкой.
Секрет среды Codex не становится переменной сервера WordPress автоматически.

Новые заявки сначала сохраняются в WordPress, затем сайт отправляет уведомление
в выбранный чат, после чего пытается отправить email. Telegram использует таймаут
8 секунд и проверку TLS. Для каждой заявки показан отдельный статус Telegram.
«Отправлено в Telegram» означает, что API вернул ID созданного сообщения;
это не подтверждение прочтения человеком. Ошибка или отсутствие настройки не
отменяет сохранение заявки. Длинные уведомления сокращаются со ссылкой на полный текст.
Повторная отправка той же формы не дублирует уведомление. Старые заявки автоматически
не рассылаются. Для проверки подключения есть кнопка «Отправить тест в Telegram».

Проверки: `php tests/telegram.php` — HTTP-вызовы заменены заглушками, включая
успех, 403/429/500, сетевой сбой, некорректный JSON, ограничение Unicode,
права администратора, CSRF и отсутствие токена в HTML/статусах.
