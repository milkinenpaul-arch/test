## Исходники и сборка

Основные файлы:

- `datatour-bf26.html`, `datatour-bf26.css`, `datatour-bf26.js` — разметка, стили и интерфейс.
- `datatour-bf26-config.json` — даты, полные списки, ссылки, настройки интеграций; `news-content.json` — статьи.
- `assets/hero-*.webp`, `assets/image-provenance.json` — адаптивные версии исходной фотографии из репозитория. Это иллюстрация побережья, а не фотографии перечисленных отелей.
- `wordpress/datatour-bf26-compatible/datatour-bf26.php`, `leads.php`, `templates/landing.php`, `assets/shell.css` — плагин, серверный обработчик и шаблон.
- `scripts/build-package.py`, `scripts/build-deployment.py`, `scripts/build-rollback.py` — сборка, обновление с проверкой контрольных сумм и подготовка отката.
- `tests/forms.php`, `tests/frontend.cjs` — проверки с имитацией почты и внешнего модуля.
- `blueprint.json`, `datatour-bf26-preview.html` — новый Playground и автономный просмотр. Автономный HTML сам по себе не имеет обработчика WordPress.
- `downloads/datatour-bf26-2026-10-14/datatour-bf26-production-1.4.2.zip` — установочный пакет; рядом пакет возврата исходной версии.

Сборка и локальные проверки:

```sh
cd /workspace/test
python3 scripts/build-package.py
node --check datatour-bf26.js
node tests/frontend.cjs
npm --cache /workspace/scratch/npm-cache exec --yes --package=@php-wasm/cli@3.1.58 -- php-wasm-cli tests/forms.php
```

При следующем изменении увеличьте версию в конфигурации, HTML и главном PHP-файле, включая пути обработчика и ресурсов. Сборка хранит ресурсы по версии; не перезаписывайте опубликованную папку прежней версии.

## Как обновлён WordPress клиента

Использована авторизованная админка и существующий `datatour-bf26-compatible`. На сервере WordPress 4.9.8 / PHP 5.4.45. Стандартная запись PHP через редактор плагинов возвращалась к старому файлу из-за проверки loopback, поэтому применён небольшой временный плагин обновления.

Он сверяет контрольные суммы действующих файлов, записывает новые ресурсы и обработчик в отдельную папку версии, а затем атомарно меняет главный файл существующего плагина. Страница, шаблон, тема и общие настройки не заменяются. Старые ресурсы сохранены. Вспомогательные плагины после проверки деактивированы.

На этом сайте не нужно повторно загружать страницу: обновление уже опубликовано. На другом WordPress установите производственный ZIP через **Плагины → Добавить новый → Загрузить плагин**; создайте нужную страницу с `[datatour_bf26]`, выберите шаблон «Datatour — отдельный лендинг». Сервер должен позволять отправку почты; установка пакета не подтверждает доставку. Ссылки на новости в пакете указывают на опубликованные статьи клиента; для другого сайта создайте статьи и замените ссылки в конфигурации. Не устанавливайте старый демонстрационный плагин одновременно с совместимым.

## Откат без скачивания файлов

В админке оставлен **неактивный** вспомогательный плагин **Datatour — Restore original page implementation (1.4.2)**. Его активация возвращает главную программу лендинга к исходной версии до этого задания; перед заменой он проверяет контрольные суммы текущего файла и сохранённых исходных ресурсов. Если после задания код изменился, он отменит возврат.

1. Откройте **Плагины → Установленные**; временные плагины `Datatour scoped update` должны оставаться выключенными.
2. Для полного возврата страницы активируйте **Datatour — Restore original page implementation (1.4.2)**. Это возвращает прежний дизайн и демонстрационные формы: отправка заявок этой версии больше не подключена.
3. Проверьте прежний URL, затем деактивируйте вспомогательный плагин восстановления. Основной совместимый плагин оставьте активным.
4. Если нужно убрать добавленные статьи, переведите записи ID 291–293 в черновики. Они не удаляются автоматически.

Для возврата только последнего небольшого обновления можно вместо полного восстановления активировать только последний `Datatour scoped update`, затем нажать его кнопку **Roll back this Datatour update** и деактивировать помощник. Не активируйте несколько помощников обновления одновременно. Дополнительный ZIP отката сохранён в репозитории; он предназначен именно для контрольных сумм этой публикации.

Частные исходные резервные копии и снимки до записи находятся вне репозитория в `/workspace/scratch/bf26-refresh/backups/`; они не содержатся в установочном ZIP. Не сохраняйте cookies, административные ответы, пароли или заявки в Git.

## Что требуется для оставшейся части

Среда пока блокирует обращения к Google Drive и Tourvisor сетевым прокси (HTTP 403). В сохранённый черновик настроек уже добавлены нужные домены. Откройте настройки среды, сохраните изменения и **опубликуйте среду**: сохранённый черновик сам по себе не меняет действующие разрешения.

Четыре отзыва уже опубликованы из скриншотов, приложенных заказчиком отдельно. После применения разрешений нужно получить PDF по предоставленной ссылке, извлечь платёжные логотипы и проверить конечные карточки Datatour в Яндекс/Google. Если PDF требует доступа Google-аккаунта, понадобится доступный исходный файл. Нельзя восстанавливать скрытый текст Ольги Б. и представлять отзывы об автобусных поездках как отзывы об авиатурах.

Отдельно необходима проверка настоящего Tourvisor, карты и внешних ссылок, а также подтверждение получения уже отправленного тестового письма. Для подключения счётчиков нужны действующие идентификаторы аналитики; для исторических кейсов — факты заказчика.

## Playground

Запустите **New → From a URL** с адресом:

https://raw.githubusercontent.com/milkinenpaul-arch/test/main/blueprint.json

Blueprint устанавливает актуальный производственный плагин в новую копию WordPress, создаёт страницу и три статьи для просмотра. Структура Blueprint проверена официальной схемой; запуск самой копии Playground и доставка почты в ней не подтверждены. Открытая раньше копия не обновляется; правки в WordPress клиента не возвращаются автоматически в GitHub. Настройки постоянных ссылок Blueprint относятся только к свежему Playground, а не к WordPress клиента.
