# Google Sheets ↔ GitHub

Подготовлено двустороннее соединение таблицы
https://docs.google.com/spreadsheets/d/1ojVZc3m0Xk0emdHye4zvwIBNUUkSA1O05xiHdQb424M/edit
с репозиторием `milkinenpaul-arch/test`, веткой `main`.

**Статус: реализация подготовлена и проверена на искусственных данных. Доступ к настоящей Google-таблице ещё не авторизован; фактическая синхронизация не подтверждена.** В этой облачной сессии отсутствует Google Sheets-коннектор, обращения к Google и API GitHub блокируются сетью. Вход в локальный браузер пользователя не передаётся облачному Chromium.

## Что соединяется

Все обычные табличные вкладки (GRID), как указал пользователь. Их значения и формулы хранятся в `data/google-sheets/workbook.json`. Вкладки отслеживаются по постоянному числовому `sheet_id`, а не по порядку или названию. Ссылка с `gid=0` открывает первую вкладку; она не отменяет согласованный выбор всех вкладок.

- Изменение в Google переносится в GitHub.
- Изменение `workbook.json` в `main` переносится в Google.
- Первый запуск только импортирует Google; он не перезаписывает исходную таблицу.
- Новая вкладка Google импортируется автоматически. Переименования и удаление вкладок выполняются в Google. Добавление/удаление/переименование вкладок через JSON не поддерживается.
- При записи меняются только отличающиеся значения/формулы ячеек. Форматирование, заметки, размеры сетки и настройки таблицы не перезаписываются. Перестановка массивов строк означает изменение значений на этих координатах, а не вставку строк с переносом форматирования.

Это соединение таблицы с файлами GitHub. Для преобразования её столбцов в карточки сайта понадобится отдельное сопоставление полей после получения реальной структуры. Публикация WordPress не запускается этим workflow.

## Однократная активация

1. В Google Cloud выберите или создайте проект и включите **Google Sheets API**: https://console.cloud.google.com/apis/library/sheets.googleapis.com . Создайте сервисный аккаунт в **IAM и администрирование → Сервисные аккаунты**; в его разделе **Ключи → Добавить ключ → Создать новый ключ** выберите JSON. Отдельные роли доступа к проекту для чтения этой таблицы не требуются.
2. Откройте исходную таблицу → **Настройки доступа** и добавьте `client_email` созданного сервисного аккаунта с ролью **Редактор**. Это доступ к конкретной таблице, не ко всему Google Диску.
3. В [Secrets репозитория](https://github.com/milkinenpaul-arch/test/settings/secrets/actions) добавьте секрет **`GOOGLE_SHEETS_SERVICE_ACCOUNT_JSON`** с полным содержимым JSON-ключа.
4. В [Actions](https://github.com/milkinenpaul-arch/test/actions) откройте **Google Sheets ↔ GitHub → Run workflow**. Сначала выберите **dry-run**, без разрешения конфликтов. Отчёт доступен в артефакте `google-sheets-sync-report`.
5. Если план верен, запустите **apply**. Появятся `workbook.json` и `sync-state.json`, исходная Google-таблица при первом импорте останется прежней.
6. В **Settings → Secrets and variables → Actions → Variables** добавьте **`GOOGLE_SHEETS_SYNC_ENABLED` = `true`**. После этого обмен выполняется по расписанию примерно каждые 10 минут и после изменений относящихся к синхронизации файлов в `main`. Планировщик GitHub может задерживать запуск. Пока переменная не установлена, автоматические записи не выполняются.

Workflow использует встроенный `GITHUB_TOKEN`, отдельный GitHub PAT не требуется. Запись в `main` должна быть разрешена правилами репозитория для workflow; принудительный push не используется.

## Конфликты и одновременные правки

Сравниваются Google, GitHub и контрольная сумма последнего подтверждённого снимка.

- Изменена только одна сторона — её значения переносятся на другую.
- Обе стороны уже одинаковы — обновляется только состояние синхронизации.
- Разные вкладки изменены с разных сторон — каждая синхронизируется независимо.
- Одна вкладка изменилась с обеих сторон — весь запуск останавливается до любых записей. Даже изменения разных ячеек одной вкладки требуют явного выбора; автоматического «победителя по времени» нет.

Посмотрите обе версии и артефакт отчёта. Для явного решения запустите workflow с **apply**, `resolve=google` или `resolve=github` и числовыми `sheet_ids` конфликтующих вкладок, например `0,123456`. Выбранная сторона станет источником только для перечисленных вкладок. Перед использованием `github` проверьте итоговые значения, которые будут записаны в Google.

Перед записью Google читается повторно, после — сверяется результат. Записываются только изменённые ячейки одной атомарной операцией `batchUpdate`. У Google Sheets API нет используемой здесь транзакционной блокировки интерактивного редактирования: очень короткое окно между проверкой и записью не исключено. Изменение во время/после записи останавливает продвижение состояния; автоматического повторения неопределённого POST нет.

Если GitHub отклонит push из-за новой правки в `main`, workflow не делает force-push. Следующий запуск повторно сопоставит данные и остановится при конфликте. Контрольные суммы нельзя редактировать вручную ради обхода проверки.

## Проверка и локальный запуск

```sh
python -m pip install -r integrations/google-sheets/requirements.txt
python tests/sheets_sync.py
python scripts/sync-google-sheets.py --dry-run --report /tmp/sheets-plan.json
```

Для реального чтения/записи переменная окружения `GOOGLE_SHEETS_SERVICE_ACCOUNT_JSON` должна содержать ключ, предоставленный через менеджер секретов. По умолчанию CLI делает только предварительный расчёт. Для записи требуется явный `--apply`.

Проверены 20 офлайн-контрактов: оба направления, импорт всех вкладок, формулы/типы, конфликты, одновременные правки, неопределённый результат записи без повторного POST, удаление/переименование, явное разрешение конфликтов, ограничения изменений и подпись OAuth для Google. Ключи и реальные данные таблицы в тестах не используются.

Конфигурация: `config.json`. Ограничения по умолчанию — 100000 позиций ячеек на вкладку, до 2000 изменённых ячеек за запуск. Расширение сетки Google выполняется в самой таблице; синхронизация не вставляет строки/столбцы и не расширяет их автоматически.
