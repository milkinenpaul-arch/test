# Datatour — «Чёрная пятница 2026»: код для WordPress

Экспорт текущего интерактивного макета. 15 блоков, 25 демонстрационных карточек, связанные фильтры и формы. Обычные HTML, CSS и JavaScript, без сборки, фреймворков и внешней библиотеки иконок. Фотографии для демонстрации встроены в JavaScript; перед запуском их следует заменить своими.

## Правки через GitHub и WordPress Playground

`blueprint.json` запускает свежий WordPress, загружает HTML, CSS и JavaScript из ветки `main`, подключает минимальную тему предпросмотра и создаёт страницу `/black-friday-2026/`. Плагины и сборка не нужны. Нативный блок «Произвольный HTML» хранится в записи страницы; отдельные гостиничные записи и поля в админке не создаются.

### Как вносить правки

1. Меняйте `datatour-bf26.html` для текстов и структуры, `datatour-bf26.css` для оформления, `datatour-bf26.js` для отелей, настроек и взаимодействий. Можно поручать эти правки Codex.
2. Сохраняйте согласованную версию коммитом в `main`. Изменения в другой ветке не попадут в этот предпросмотр до слияния.
3. Открывайте Blueprint из этого репозитория через Playground → New → From a URL. Публичный URL Blueprint: `https://raw.githubusercontent.com/milkinenpaul-arch/test/main/blueprint.json`.
4. Для следующего предпросмотра запускайте Blueprint заново в новом Playground. Загружать ZIP вручную не нужно. Уже открытая страница не обновляется сама при появлении коммита.

Если GitHub временно отдаёт закешированную версию файлов, повторите запуск позже; это не мгновенная двусторонняя синхронизация.

### Какие данные сохраняются

- GitHub — основная версия HTML, CSS и JavaScript и история правок.
- Каждый запуск Blueprint создаёт свежий WordPress и восстанавливает страницу из HTML в GitHub. Правки текста в админке и настройки предыдущего Playground не переносятся в новый запуск.
- Для работы только в WordPress открывайте сохранённый Playground через Your Playgrounds и редактируйте ту же страницу, без нового импорта. Такие изменения нужно отдельно переносить обратно в исходники, если они должны стать основной версией.
- Export to GitHub — отдельное действие экспорта выбранных файлов через pull request; оно не включает постоянную автоматическую синхронизацию.

Blueprint проверен по официальной JSON-схеме Playground и запущен из опубликованного GitHub-репозитория. В браузере подтверждены 15 блоков, один H1, две формы, 25 карточек, переключение на 10 зимних вариантов, перенос выбранного отеля и сообщение «Демонстрация: данные проверены, отправка ещё не подключена».

[Открыть страницу в WordPress Playground](https://playground.wordpress.net/?blueprint-url=https%3A%2F%2Fraw.githubusercontent.com%2Fmilkinenpaul-arch%2Ftest%2Fmain%2Fblueprint.json&random=ieyph4ikwhc). Для получения новой версии после коммита используйте New → From a URL с URL Blueprint выше. Файл не содержит токенов и не публикует базу WordPress.

## Просмотр и работа в Codex

Откройте `datatour-bf26-preview.html` в браузере для просмотра без WordPress. При дальнейших правках основными исходниками служат отдельные HTML, CSS и JavaScript; после изменений обновляйте самодостаточный предпросмотр из этих трёх файлов. Зависимости и сборка не требуются.

Сохраняйте порядок 15 блоков, единый массив из 25 отелей, локальные взаимодействия и изоляцию внутри `#dt-bf26`. Не подключайте отправку форм, CRM, оплату, аналитику, Tourvisor и карту без отдельного задания. Не заменяйте демонстрационные данные вымышленными ценами, отзывами, сроками и контактами.

ZIP — комплект исходников, а не установочный архив темы или плагина.

## Размещение: шесть шагов

1. **Создайте страницу** в WordPress и задайте адрес `black-friday-2026`. По возможности выберите полноширинный шаблон без стандартной шапки, подвала и заголовка страницы: они уже есть в макете. Наличие и название такого шаблона зависят от темы; если его нет, эту часть нужно настроить в установленной теме. Не отключайте шапку и подвал остальных страниц.

2. **Вставьте HTML.** Скопируйте содержимое `datatour-bf26.html` в блок «Произвольный HTML» или соответствующий HTML-элемент вашего редактора. Только один экземпляр контейнера `#dt-bf26` на странице. CSS и JavaScript не вставляйте как видимый текст в этот блок.

3. **Разместите файлы CSS и JavaScript.** Для варианта с дочерней темой создайте в её папке каталог `datatour-bf26` и загрузите туда `datatour-bf26.css` и `datatour-bf26.js`: `/wp-content/themes/[папка активной дочерней темы]/datatour-bf26/`. Это можно сделать через файловый менеджер хостинга или SFTP. HTML остаётся в содержимом страницы.

4. **Подключите стили и скрипт.** Добавьте приведённый ниже PHP-фрагмент в существующий `functions.php` дочерней темы внутри PHP-кода, не заменяя содержимое файла. Он подключает оба файла только на странице с адресом `black-friday-2026`, JavaScript — в нижней части страницы. Если адрес другой, измените его в `is_page(...)`. При уже доступном механизме пользовательского кода альтернативой служат CSS из файла в поле CSS и JavaScript из файла в поле JavaScript с запуском на этой странице; не подключайте оба варианта одновременно. В поле, которое ожидает HTML, JavaScript оформляется как `<script>…</script>`, в поле JavaScript — без этих тегов. Если редактор удаляет скрипты, используйте внешнее подключение через дочернюю тему. Если дочерней темы и доступных полей пользовательского кода нет, точный вариант подключения зависит от установленной темы и доступа к файлам.

   ```php
   // Добавить в functions.php дочерней темы, внутри PHP-кода.
   add_action('wp_enqueue_scripts', function () {
       if (!is_page('black-friday-2026')) {
           return;
       }
       $dt_bf26_dir = get_stylesheet_directory() . '/datatour-bf26/';
       $dt_bf26_url = get_stylesheet_directory_uri() . '/datatour-bf26/';
       $dt_bf26_css = $dt_bf26_dir . 'datatour-bf26.css';
       $dt_bf26_js  = $dt_bf26_dir . 'datatour-bf26.js';

       if (is_file($dt_bf26_css)) {
           wp_enqueue_style(
               'datatour-bf26-css',
               $dt_bf26_url . 'datatour-bf26.css',
               array(),
               (string) filemtime($dt_bf26_css)
           );
       }
       if (is_file($dt_bf26_js)) {
           wp_enqueue_script(
               'datatour-bf26-js',
               $dt_bf26_url . 'datatour-bf26.js',
               array(),
               (string) filemtime($dt_bf26_js),
               true
           );
       }
   }, 20);
   ```

5. **Замените демонстрационные данные.** Тексты и контакты находятся в пронумерованных секциях HTML, цветовые переменные — в начале CSS, настройки `photos`, `campaign`, `scenarios` и массив `hotels` — в JavaScript. В `photos` вместо встроенных строк `data:image/jpeg;base64,…` можно поставить полные URL фотографий из медиатеки WordPress. До подтверждения сроков оставьте `campaign.start` и `campaign.end` равными `null`. Формы, Tourvisor, карта, документы, контакты, реальные ссылки и материалы требуют отдельного подключения; отправка сейчас остаётся демонстрационной.

6. **Проверьте страницу на сайте** после сохранения и очистки кеша: ширины 360, 768 и 1440 px, отсутствие второй шапки и второго H1 от темы, меню и якоря, фильтры, стрелки и свайп, увеличение скриншотов, FAQ, перенос отеля и ошибок формы. Проверяйте опубликованный предпросмотр: внешний CSS и скрипт могут не загружаться внутри редактора. До подключения обработчика правильный результат формы — «Демонстрация: данные проверены, отправка ещё не подключена».

## Где менять данные

- **Цвета и отступы:** переменные `--dt-accent`, `--dt-dark`, `--dt-paper`, `--dt-radius`, `--dt-space`, `--dt-width` в начале CSS.
- **Фотографии:** объект `photos` в JavaScript; ключи `beach`, `resort`, `pool`, `coast`, `palms`. Это заменяемые демонстрационные изображения, не фотографии перечисленных отелей.
- **Сроки:** объект `campaign`. Только после подтверждения можно задать ISO-строки с часовым поясом, например формат `YYYY-MM-DDTHH:mm:ss+03:00`. Окончание должно быть позже начала. Календарная Чёрная пятница не подставляется автоматически.
- **Отели:** массив `hotels` из 25 отдельных объектов. Название, направление, параметры, причины выбора и ограничение — строки; `price: null` показывает «Расчёт на ваши даты». При заполнении `price` выводится сумма с валютой и пояснением «на весь состав». Используйте цену на весь указанный состав туристов.
- **Ключи фильтров:** сезон `summer` / `winter`; сценарий `family` / `couple` / `friends` / `discover` / `service`; бюджет `rational` / `comfort` / `premium`. Значения должны соответствовать ключам в настройках. ID отелей должны оставаться уникальными.
- **Формы:** идентификаторы `dt-quick-form` и `dt-final-form`; проверка — функция `validateForm`. Скрытые поля `scenario`, `hotelId`, `budgetLevel` сохраняют текущий выбор. В макете сетевых запросов нет. Сообщение об успешной отправке можно показывать только после реального ответа подключённого обработчика.
- **Tourvisor и карта:** контейнеры `dt-tourvisor-container` и `dt-map-container`. Виджеты в этот комплект не входят.
- **Отзывы и блог:** слоты и подписи демонстрационные; реальных отзывов, опубликованных статей и их ссылок нет.

Статический HTML не создаёт нативные блоки Gutenberg, записи отелей и публикации в админке. После установки этого варианта тексты меняются в HTML, данные отелей — в JavaScript. Если требуется редактировать отели через отдельные поля в админке, это следующая задача по интеграции WordPress.
